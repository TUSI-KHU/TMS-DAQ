## 현재 버전과의 관계

종료 직렬화, STALL 제한, 세션 큐 분리와 입력 두 번의 복구 검증은 현재에도 유지한다.
현재 버전에는 DAQ PC 로컬 GUI, 영구 보정 프로파일 불러오기, MA80 공통 처리,
HDF5/CSV 결과 분석, GUI 저장 폴더 선택이 추가됐다. 원격 초기화는 별도 SSH,
로컬 초기화는 `pkexec`로 실행한다. 보관용 LPF는 유지하되 기본 화면·CSV 분석은
80샘플 이동평균을 사용한다. 아래의 과거 시험 결과를 새 장치의 완료 판정으로
바꾸거나, 과거 백업 경로가 현재 PC에도 존재한다고 가정하지 않는다.


## 대상 환경

- Pi: `tms@10.47.0.2`, Ubuntu 22.04 ARM64, `5.15.0-1110-raspi`.
- USB-4704: USB `1809:4704`, `/dev/daq0`, 5,000 samples/s/channel, AI0·AI1.

## 확인한 원인

실제 반복 시험 중 6~7번째 취득/종료 부근에서 STOP ioctl이 10초 이상,
close가 추가로 약 5초 지연되고 다음 캘리브레이션이 실패하는 현상을 재현했다.
이때 SSH와 agent의 PING 응답은 유지됐다.

드라이버 진단을 추가하니 보조 상태 조회 `GET_USB_FLAG`
(`request=0x7f`, `value=0x000e`)가 `-EPIPE`(USB STALL)를 반복 반환했다.
기존 드라이버는 반환 오류를 무시하고 bulk 전송 완료마다 다시 조회했다.
이후 해당 제어 경로에서 `-ETIMEDOUT`이 발생하고 STOP/CLOSE도 응답하지 않았다.
STALL 반복을 중단한 뒤 동일한 반복 시험이 통과했다. 따라서 현재 장치의
이 요청에 대한 펌웨어 비호환과 반복 조회가 주요 원인으로 판단된다.
이번 시험 구간에는 Pi 저전압 경고가 관찰되지 않았다.

별도로 다음 소프트웨어 결함도 확인하고 수정했다.

- 정상 STOP의 URB 취소까지 비동기 stop 작업으로 예약해 다음 취득에 영향을
  줄 수 있는 경쟁 조건.
- USB 종료 오류를 드라이버와 Python 양쪽에서 성공처럼 무시하던 경로.
- USB close가 멈추면 HDF5 마감도 지연되는 종료 순서 및 STOP watchdog 부재.
- 세션 사이에 남은 화면용 큐/필터 배치, 오래된 HEALTH에 의해 다시 활성화되는 버튼.
- 초기화 중 재접속 실패가 건강한 SSH 터널까지 재생성하던 동작.
- 모든 배경 오류를 중첩 모달창으로 띄우고 초기화 진행 상태까지 해제하던 동작.

## 변경

- `GET_USB_FLAG`를 최대 4 Hz로 제한하고 STALL이면 해당 USB 연결에서 더 이상
  반복하지 않는다. 정상 펌웨어에서는 조회를 유지한다.
- 정상 취소 URB는 오류 stop 작업을 예약하지 않으며 START/STOP 경계에서 이전
  작업을 정리한다. 펌웨어 STOP 응답 전까지 bulk 입력을 유지하고 종료를 직렬화한다.
- 실제 STOP 실패를 호출자에게 전달한다. 로그를 먼저 마감하고 USB를 닫으며,
  종료 watchdog 실패 시 재시작 대신 복구 필요 상태를 유지한다.
- telemetry에 세션 ID를 추가하고 세션/연결 경계의 오래된 화면 데이터를 폐기한다.
- 초기화 중 재접속을 일시 중지하고 SSH 터널은 유지한다. 단일 초기화 잠금을
  사용하고, 노드 존재가 아니라 입력 취득/종료 2회 및 GUI 재연결을 검증한다.
- 배경 연결 오류는 상태/콘솔로 알리고, 사용자 명령 오류는 단일 비모달창으로
  표시한다. 캘리브레이션 오류는 해당 창 안에 표시한다.

제한: STALL 펌웨어에서는 **장치 내부 FIFO 초과 플래그 조회가 불가능**하다.
호스트 버퍼 초과/취득 중단/로그 인덱스 누락 검사는 유지되지만 이것이 장치 내부
FIFO 상태를 대신 증명하지는 않는다. 드라이버는 이 제한을 커널 로그에 명시한다.

## 검증 결과

- 자동 테스트 71개 통과. 종료 지연, 로그 마감, 중복 초기화, 세션 큐 분리,
  상태 전환, SSH 유지, 알림창 X 닫기를 포함한다.
- 실제 Pi에서 캘리브레이션→취득→저장→SFTP 다운로드 20회 통과.
- 각 HDF5의 원시값/물리값/LPF 데이터 길이, 0부터 시작하는 연속 샘플 인덱스,
  gap/trigger 이벤트 없음 확인.
- 같은 SSH 연결에서 DAQ 초기화 2회 통과(각 약 7.47초).
- 실제 GUI의 측정/종료 3회, 종료 후 캘리브레이션, 초기화/재연결 통과.
- 약 60초 연속 취득 후 HDF5 저장/다운로드 및 즉시 재측정 통과
  (299,800 samples, 연속 인덱스·로그 메타데이터 일치·gap 이벤트 없음).
  START/STOP은 장치 클록에 동기화되지 않고 미완료 USB 전송은 종료 시 폐기하므로
  정확히 300,000 samples를 요구하는 시험은 아니다.
- 재빌드된 실행 파일의 `--self-test` 및 모의 telemetry 연결 smoke test 통과.

시험은 입력 취득 경로를 검증했으며 Nano 세션 ARM/점화 명령은 보내지 않았다.
센서의 기계적 정확도나 장시간 운용 보증을 의미하지 않는다.
